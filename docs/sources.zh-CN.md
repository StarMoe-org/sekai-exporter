# 来源

[English](sources.md)

来源负责提供输入：某个区服的当前版本、其清单，以及按名称获取的资源包字节。字节一经取得即成为输入，以其 SHA-256 标识。此后的所有派生只通过哈希识别输入，与字节的出处无关。

## 来源的种类

| 来源 | 提供的内容 | 用途 |
|---|---|---|
| `cp` | 日服与美服所用分发服务的版本、清单与资源包 | `jp`、`en` |
| `nuverse` | 国服、台服与韩服所用分发服务的版本、清单与资源包 | `cn`、`tw`、`kr` |
| `dir` | 本地目录中已有的资源包 | 离线运行与测试 |
| `apk` | 客户端安装包中的 player data，以及其中包含的客户端身份 | `client` 来源 |
| `store` | 部署方在自有私有 store 中保留的输入 | 惰性求值、无服务器部署与历史版本 |

一个区服可以按顺序配置多个来源，例如先查 `store`，store 中没有该资源包时再查 `cp`。

游戏数据表有独立的来源：`git` 按指定提交读取数据表转储仓库，为默认来源；`api` 读取游戏接口，需要账号。提交号或接口版本记入该版本的[数据表身份](#版本身份)，转换器所读取的每条记录的哈希计入该转换器的指纹。

## 区服表

各区服的主机、应用标识、渠道与平台，以及客户端身份（应用版本、应用哈希、用户代理与设备型号），存放于本仓库的一份数据文件中，配置可覆盖其中任意一项。这些值是导出器正常工作的前提，且任何安装了客户端的人都能读取到。**区服表永不包含密钥。**

## 版本发现

客户端身份取自以下各项中第一个可用者：

1. 作为 `apk` 输入提供的客户端安装包；
2. 配置；
3. 外部的当前版本信息源。

候选值只有经该区服的版本接口确认、且比当前值更新时才会被采用。对于分发路径以资源包版本为键的区服，若版本接口不识别应用版本 `x.y.z`，则改以 `x.y.0` 重试。以 `force` 设定的值视为固定值，在被移除之前不会被版本发现替换，可用于回滚。各区服独立检查，一个区服的失败不会延误其他区服。

## 版本身份

区服的状态分三部分，各自决定不同的事。

| 部分 | 字段 | 变化时 |
|---|---|---|
| **资产身份** | `cp`：asset version、asset hash、profile 与资源主机哈希。`nuverse`：版本端点返回的值 | 清单与资源包的地址改变，因此重新读取清单并运行 P1 至 P3 |
| **数据表身份** | 游戏给出的 data version，以及数据表修订号：转储仓库的提交号，或 `api` 来源的接口版本 | 只有数据表的记录可能不同。跳过 P1 至 P3，沿用该资产身份的索引，只重新求值记录发生变化的资产 |
| **客户端身份** | 应用版本、应用哈希与多人游戏版本 | 随版本记录，没有资产依赖它。`cp` 的资源主机哈希要凭它查询，所以资产身份经由它读取 |

data version 与数据表修订号是两个字段，因为来源不同：前者由游戏分配，后者由保存转储的仓库分配。任一字段变化，数据表身份即变化。

已提交的版本由资产身份与数据表身份共同命名，因此只更新数据表也是一个新版本，并与上一版本共享所有未受影响的产物。

## 声明哈希与内容哈希

清单的每一行声明一个资源包哈希（`cp` 为 `hash`，`nuverse` 为 `crc`），`cp` 还声明 `crc` 与大小。它们与标识已存储输入的 SHA-256 是两类不同的哈希：

- **声明哈希**决定资源包是否重新获取。声明哈希与上一次运行相同的资源包不会重新下载，沿用已存储的字节与索引。声明哈希不变时其余声明字段也可能变化，因此只记录、不比较。
- **内容哈希**是导出器在字节到达时算出的 SHA-256。下载之后的一切都以它标识资源包。

声明哈希是标签，不是文件内容的摘要。声明哈希相同的资源包，在不同版本的路径下可能返回不同的字节（包括流式数据），声明哈希不同的资源包也可能包含完全相同的对象。因此运行时不会重复下载来比较，增量工作依据对象及其读取的资源范围的内容，见[管线](pipeline.zh-CN.md#不变式)。

## 凭据

清单与接口响应均经过加密。解密所用的密钥、加密 CRI 音视频所用的密钥，以及日服所用的访客账号，均属于**密钥**。

- 每个密钥都有一个名称，其值读取自同名的环境变量，或读取自仓库以外的密钥文件。
- 密钥的值永不写入日志、报告、目录或资产文档。报告只记录所用密钥的名称，不记录其值。
- 访客账号由部署方通过一条单独的命令创建一次，此后作为密钥保存并复用。运行过程中不创建账号。
- 示例配置中每个密钥均留空，并注明其值须由使用者从自己的客户端取得。

## 网络

每个来源均可配置代理（HTTP 或 SOCKS）、并发上限、速率上限、带退避的重试与主机轮换。清单不提供内容摘要，其声明的大小也不是下载内容的大小，因此导出器按响应长度核对每个资源包，并记录其 SHA-256。

## 输入 store

保留原始输入的部署将其作为 `store` 来源使用。惰性求值与无服务器部署由此从该 store 读取输入，凭据只需存在于负责获取资源包的机器上，且可以对较早的版本重新求值。**输入 store 包含游戏数据，必须设为私有**，不得与输出一同发布。
