# 路径索引

[English](path-index.md)

路径索引把视图中的每个路径映射到存放该文件的对象。模块：`sekai-format` 中的 `paths`。`sekai-publish` 为视图的每次发布写出一份，`sekai-serve` 读取它（见[服务](../serving.zh-CN.md)）。格式版本：1。

## 1. 运行时

用 store 中的对象回答路径请求的解析器，例如 `sekai-exporter serve` 以及存储桶前的边缘 worker。

## 2. 内容

**根**包含键 `format`（`"path-index"`）、`version`、`view`、`published_version`、`revision`、`files`（路径数）与 `chunks`。`chunks` 按路径顺序为每个分块列出 `{ "first", "sha256", "files" }`：分块的第一个路径、分块对象的小写十六进制 SHA-256，以及分块中的路径数。

**分块**保存按字节序连续的一段路径。每个路径记录：

| 字段 | 值 |
|---|---|
| 路径 | 视图中的路径，UTF-8，不以 `/` 开头 |
| SHA-256 与扩展名 | 对象在 store 中的名称，`<aa>/<sha256>.<extension>` |
| 大小 | 字节数 |
| 媒体类型 | 媒体类型 |

根存为 `<aa>/<sha256>.json`，每个分块存为 `<aa>/<sha256>.paths`。视图的指针在 `paths` 下指向根（见[发布文档](publication.zh-CN.md)）。

## 3. 来源

路径、对象、大小与媒体类型取自该视图这次发布的文件，按路径的字节序排列。若某路径的 SHA-256 的前四个字节按大端 32 位整数读出是 2048 的倍数，分块在该路径之后结束；否则在第 8192 个路径之后结束；最后一个分块以最后一个路径结束。因此一个分块平均有 2048 个路径；改动一个路径只改变包含它的分块，除非这次改动移动了分块边界。

## 4. 容器

根是 UTF-8 JSON，不含无意义的空白，键按上文顺序排列。

分块是二进制格式。标为 *varint* 的整数是无符号 LEB128。

| 部分 | 编码 |
|---|---|
| 魔数 | 四个字节 `SKPI` |
| 版本 | 一个字节，`1` |
| 扩展名 | 一个 varint 计数，然后按首次出现的顺序给出每个扩展名：varint 字节长度及其 UTF-8 字节 |
| 媒体类型 | 同上，用于媒体类型 |
| 路径 | 一个 varint 计数，然后按顺序给出每个路径：与上一个路径共享前缀的 varint 长度（第一个为 0）、其余部分的 varint 长度及其字节、SHA-256 的 32 个字节、varint 大小、扩展名表中的 varint 序号、媒体类型表中的 varint 序号 |

## 5. 正确性

读取方拒绝以下分块：魔数或版本不同；计数或长度越过末尾；序号越界；路径不是合法的 UTF-8 或不按严格递增的字节序排列；最后一个路径之后还有字节。读取方也拒绝分块不按第一个路径严格递增排列的根。

测试从已知的发布计划构建索引，检查：每个路径都解析到它的文件；第一个之前、文件之间与最后一个之后的路径都解析不到；其他路径改变时，未变的区间保留其分块；分块解码后与编码前的文件一致。

## 6. 版本

格式版本：1。上述任何一项变化都会使版本变化。
