# 管线

[English](pipeline.md)

管线是[派生图](architecture.zh-CN.md)的急切求值器。一次运行在单个进程中处理全部已配置区服的当前版本，所有区服共用一个目录与一个派生缓存。

## 阶段

| 阶段 | 工作 | 产出 |
|---|---|---|
| P0 计划 | 读取各区服的[资产身份与数据表身份](sources.zh-CN.md#版本身份) | 若两者均与上一次完整运行相同，则无需工作；若只有数据表身份变化，则跳过 P1 至 P3，沿用该资产身份的索引 |
| P1 清单 | 下载并解析清单，按名称选取资源包 | 资源包列表，含声明的哈希、大小与依赖 |
| P2 取件 | 下载所选资源包，在数据流入的同时完成去混淆与哈希计算，并写入 store | 以内容哈希标识的资源包输入 |
| P3 索引 | 对每个资源包读取每个对象的字段，大数组按长度跳过；记录类、名称、容器路径、内容哈希与引用 | 对象记录与引用边 |
| P3b 解析 | 全部资源包完成索引后：将外部文件解析到资源包，将 `m_Script` 解析为类名，并写出对象文档 | 该版本完全解析的对象图 |
| **屏障** | 资产的闭包与名称取决于整个版本 | |
| P4 资产计划 | 每个转换器选取其根对象，并在引用边和它声明的额外输入上计算闭包；确定名称（参见[身份](architecture.zh-CN.md#身份)）；计算指纹 | 待求值的派生；指纹已有输出的派生直接沿用，不读取任何字节 |
| P5 转换 | 在调度器下求值 convert 与 transform 派生 | 资产文档与文件字节 |
| P6 写出 | 将字节写入 store，已存在的内容跳过；在目录中记录派生 | store 对象与目录记录 |
| P7 视图 | 每个已启用的视图产生绑定；需要不同字节的视图产生 transform 派生 | 绑定 |
| P8 提交 | 核验每个已绑定的对象均以所记录的哈希存在于 store 中，随后推进版本指针 | 已提交的版本，附列其资产错误 |

## 不变式

- **增量以对象内容为单位，而非以资源包为单位。** 资源包重新打包而其中对象未变时，每个对象的哈希不变，因而每个资产的指纹不变。P2 与 P3 只对[声明哈希](sources.zh-CN.md#声明哈希与内容哈希)发生变化的资源包运行；未变化的资源包沿用其已有索引。
- **每个对象都有去向。** `ledger.tsv` 按资源包列出根对象、被转换读取、属于声明为不含资产内容的类或脚本、以及未知的对象数量，还有已读取的资源文件数量。没有未知对象且每个资源文件都被读取时，资源包才算完整。
- **转换只读取自己的闭包。** 读取其他对象会使该资产失败，错误为 `undeclared_read`，因此输出依赖的一切都在指纹之内。
- **指纹包含决定字节的全部因素**：转换器名称与版本、闭包中每个对象的内容哈希、这些对象所在资源包中每个资源条目的内容哈希、转换器读取的每条数据表记录的哈希，以及编码器的名称、版本与参数。配置不改变输出路径、格式与编码参数，这些均由转换器与视图定义。
- **资产错误与运行失败相区分。** 资产错误是对资产求值的结果，即一个具名错误，与成功的输出同样确定。它不影响其他资产，不妨碍版本提交，并随版本一并列出。由于该资产没有成功的输出，下一次运行会再次求值。成员缺失（例如资源清单列出、但来源不提供的资源包）属于资产错误。运行失败指下载失败、写入失败或进程崩溃；只有运行失败会阻止提交。
- **工作的先后不影响输出。** 每项输出只取决于其输入，目录在每批结束时按键序写入。store 的内容以及按主键排序的目录内容均与线程数和调度顺序无关。
- **提交以版本为单位，要么全部生效，要么不生效。** P8 只在核验通过后推进指针。核验失败时，以固定名称报告失败的阶段，原有指针保持不变。

## 流式求值

流式求值器从清单出发，一次一个资源包地对版本求值，不需要先为整个版本建立索引。

- **单元。** 单元是清单中的一个资源包及其窗口：该资源包本身，以及它直接或间接依赖的每个资源包。单元的根是该资源包中的根对象。它们只依据本资源包命名，闭包、声明的额外输入与脚本引用都只在窗口内追踪。
- **窗口外的引用。** 根的闭包中若有引用指向窗口外某个资源包的文件，该资产以错误 `outside_dependencies` 失败，错误信息写明引用所在的资源包与对象，以及被引用的外部文件。指向窗口外的脚本引用视为无法解析。每个这样的引用都随结果一并列出。指向不在任何资源包中的引擎文件的引用，与急切求值器一样不进入闭包。
- **分段。** 单元按清单顺序执行，连续的单元组成一段，每段的单元数与其窗口中资源包的声明大小均有上限。一段内的资源包一起打开，其派生在调度器下执行。资源包保持打开、已索引、已解析，直到窗口中含有它的最后一个单元为止，这一位置可由清单预先算出。已解析的资源包按估算的内存占用设上限。
- **结果。** 每个闭包都限于自身的窗口，因此文档、成员文件、指纹与名称都与单元如何分段、线程数多少无关。清单列全依赖且名称相同时，结果与急切求值器相同。不同资源包中得到相同名称的资产不予命名。发布在最后一个单元之后进行。
- **错误。** 无法读取、打开或索引的资源包、同名的资源包，以及清单未列出的依赖，均按资源包名报告。需要它们的单元照常执行，指向它们的引用按上述方式失败。

## 区服

全部区服在同一进程中运行。P0 至 P3 对各区服并行执行。在 P4 中，任一区服计算出的指纹可被其他区服直接找到，因此各区服之间共享的内容只转换一次。当两个区服对同一资源包声明的哈希相同时，下载阶段复用已为另一区服取得的资源包。

游戏数据表按区服分别存放。转换器的指纹只涵盖其实际读取的记录，因此即使两个区服的数据表在其他部分存在差异，只要某个资产所用的记录相同，该资产仍然共享。

## client 来源

客户端安装包内的资产经过同一条管线。P1 中的清单替换为安装包内的 player data 文件列表；P3 中，不带 type tree 的对象使用 `sekai-layouts` 中的字段布局表读取。每个对象都必须恰好读到其末尾；未能恰好读完的对象以原始字节写出，并附具名错误。
