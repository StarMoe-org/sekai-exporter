# 管线

[English](pipeline.md)

管线用下文所述的流式求值器，逐个资源包地对[派生图](architecture.zh-CN.md)求值。一次运行在单个进程中处理命令行指定的那个区服的当前版本，并使用一个目录与一份派生记录。

## 阶段

| 阶段 | 工作 | 产出 |
|---|---|---|
| P0 计划 | 读取各区服的[资产身份与数据表身份](sources.zh-CN.md#版本身份) | 若两者均与上一次完整运行相同，则无需工作；任一发生变化时重新读取清单，声明哈希未变的资源包沿用已存储的字节与索引 |
| P1 清单 | 下载并解析清单，按名称选取资源包及其依赖 | 资源包列表，含声明的哈希、大小与依赖 |
| P2 取件 | 下载所选资源包，在数据流入的同时完成去混淆与哈希计算，并写入 store | 以内容哈希标识的资源包输入 |
| P3 索引 | 每个资源包在第一个需要它的单元打开它时，读取每个对象的字段，大数组按长度跳过；记录类、名称、容器路径、内容哈希与引用。索引按资源包的内容哈希保存并复用 | 对象记录与引用边 |
| P4 单元计划 | 按名称顺序、分段逐个资源包进行（参见[流式求值](#流式求值)）：在其窗口内将外部文件解析到资源包，将 `m_Script` 解析为类名；每个转换器选取该资源包的根对象，在窗口内沿引用边和它声明的额外输入计算闭包；依据该资源包确定名称（参见[身份](architecture.zh-CN.md#身份)）；计算指纹 | 待求值的派生；指纹已有输出的派生直接沿用，不读取任何字节 |
| P5 转换 | 在调度器下求值一段中的 convert 与 transform 派生 | 资产文档与文件字节 |
| P6 写出 | 将字节写入 store，已存在的内容跳过；在目录中记录派生 | store 对象与目录记录 |
| P7 数据表 | 构建[数据表阶段](#数据表阶段)的资产 | 资产文档与文件字节 |
| P8 视图 | 每个已启用的视图产生绑定；需要不同字节的视图产生 transform 派生；发布 `index` 布局 | 绑定 |
| P9 提交 | 核验每个已绑定的对象均存在于 store 中，随后推进版本指针 | 已提交的版本，附列其资产错误 |

## 不变式

- **增量以对象内容为单位，而非以资源包为单位。** 资源包重新打包而其中对象未变时，每个对象的哈希不变，因而每个资产的指纹不变。P2 与 P3 只对[声明哈希](sources.zh-CN.md#声明哈希与内容哈希)发生变化的资源包运行；未变化的资源包沿用其已有索引。
- **每个对象都有去向。** `ledger.tsv` 按资源包列出根对象、被转换读取、属于声明为不含资产内容的类或脚本、以及未知的对象数量，还有已读取的资源文件数量。资源包的账本在窗口中含有它的最后一个单元之后结算，此后不会再有转换读取它。没有未知对象且每个资源文件都被读取时，资源包才算完整。
- **转换只读取自己的闭包。** 读取其他对象会使该资产失败，错误为 `undeclared_read`，因此输出依赖的一切都在指纹之内。
- **指纹包含决定内容的全部因素**：转换器名称与版本、资产名称、来源提供类布局时这些布局的哈希、闭包中每个对象的内容哈希，以及闭包中引用外部流数据的对象所对应的 `.resS`/`.resource` 精确字节区间（`m_StreamData` / `m_Resource`）哈希。同一资源包中不读取流数据、或自身字节区间未变的其他对象，在别的对象的流数据改变时指纹不变。编码器只有在其文件有损时才进入指纹：即声明了视频编码器（`Converter::encoders`）的资产形式所用的视频编码器。无损编码器不进入指纹：无论版本，其文件解码后都等于输入的内容。
- **已编码的内容保留其文件**：每次编码有自己的指纹，由编码器与解码后的内容构成，有损编码器再加上版本。转换再次运行且解码出相同内容时，直接复用为该内容记录的文件，不再编码。由数据表构建的资产，其指纹见[数据表阶段](#数据表阶段)。配置不改变输出路径、格式与编码参数，这些均由转换器与视图定义。
- **资产错误与运行失败相区分。** 资产错误是对资产求值的结果，即一个具名错误，与成功的输出同样确定。它不影响其他资产，不妨碍版本提交，并随版本一并列出。由于该资产没有成功的输出，下一次运行会再次求值。成员缺失（例如资源清单列出、但来源不提供的资源包）属于资产错误。运行失败指下载失败、写入失败或进程崩溃；只有运行失败会阻止提交。
- **工作的先后不影响输出。** 每项输出只取决于其输入，目录在每批结束时按键序写入。store 的内容以及按主键排序的目录内容均与线程数和调度顺序无关。
- **提交以版本为单位，要么全部生效，要么不生效。** P9 只在核验通过后推进指针。核验失败时，以固定名称报告失败的阶段，原有指针保持不变。

## 流式求值

流式求值器从清单出发，一次一个资源包地对版本求值，任何一步都不需要整个版本。

- **单元。** 单元是清单中的一个资源包及其窗口：该资源包本身，以及它直接或间接依赖的每个资源包。单元的根是该资源包中的根对象。它们只依据本资源包命名，闭包、声明的额外输入与脚本引用都只在窗口内追踪。
- **窗口外的引用。** 根的闭包中若有引用指向窗口外某个资源包的文件，该资产以错误 `outside_dependencies` 失败，错误信息写明引用所在的资源包与对象，以及被引用的外部文件。指向窗口外的脚本引用视为无法解析。每个这样的引用都随结果一并列出。指向不在任何资源包中的引擎文件的引用不进入闭包。
- **依赖。** 清单不列依赖的来源（例如目录）从资源包本身读出依赖：某资源包的序列化文件把另一资源包中的文件列为外部文件时，前者依赖后者。多个资源包含有同名文件时，以名称顺序中的第一个为准。
- **分段。** 单元按清单顺序执行，连续的单元组成一段，每段的单元数与其窗口中资源包的声明大小均有上限。一段内的资源包一起打开，其派生在调度器下执行。资源包保持打开、已索引、已解析，直到窗口中含有它的最后一个单元为止，这一位置可由清单预先算出。已解析的资源包按估算的内存占用设上限，已保存的索引只在后续单元还需要时留在内存中。
- **结果。** 每个闭包都限于自身的窗口，因此文档、成员文件、指纹、名称与账本都与单元如何分段、线程数多少无关。不同资源包中得到相同名称的资产不予命名。发布在最后一个单元之后进行。
- **错误。** 无法读取、打开或索引的资源包、同名的资源包，以及清单未列出的依赖，均按资源包名报告。需要它们的单元照常执行，指向它们的引用按上述方式失败。
- **单元记录。** 清单给出窗口中每个资源包的内容标识时，单元的结果按这些内容、各转换器的形式、类布局与资产大小上限记录，并附上单元中有根的每个转换器的版本。后续运行在这些版本不变时直接取用记录的结果，不获取该窗口，因此某个转换器的新版本只让含有其形式之根的单元重新求值。哪些对象是根由形式名决定，与该转换器是否编译进构建无关。只有窗口中没有资源包出错、且没有资产转换失败的单元才会被记录。因此转换失败的资产在下一次运行中会再次转换，转换器学会读取它时无需新版本。

## 数据表阶段

有些资产（例如[话](features.zh-CN.md)）没有根对象：每个资产由游戏数据表的记录和本版本已有的资产构建。最后一个单元之后，每个数据表转换器读取所需的表并列出它的资产，然后逐个构建。

- **输入。** 数据表转换器能看到数据表、每个资源包的资产及其形式、资产的文档和成员字节，不读取资源包中的对象。
- **引用。** 表记录需要而本版本没有的资产，记录在正在构建的资产中。因此只选部分资源包的运行，其资产会记下选择之外缺少的内容。
- **失败。** 数据表无法读取或解析属于运行失败，单个资产无法构建属于资产错误。
- **指纹。** 这些资产每次运行都会构建，不记录派生。指纹是形式及其版本、名称、每个成员的角色与内容哈希、引用以及错误的哈希，因此只在输出变化时变化。

## 区服

每个区服在各自的进程中运行，由命令行指定。派生记录保存每个已转换资产的指纹，而指纹不含区服。一个区服只在自身的记录中没有该指纹的输出时才在后续运行中再次转换该资产，而读取相同的对象就会得到该指纹。较早运行的输出目录列于 `stores`、且其中资源包的声明哈希相同时，该资源包直接从那里复用。

游戏数据表读取自该区服的 `tables` 来源。数据表记录不进入派生记录，因此数据表阶段的资产在每次运行中都会重新构建。

## client 来源

客户端安装包内的资产经过同一条管线。`--class-table` 指定一个含引擎类布局的 TPK 文件时，`sekai-exporter export` 读取 APK，或包含多个 APK 的 XAPK。`assets/bin/Data/` 下的文件，或其中 UnityFS 容器的条目，组成一个名为 `player` 的资源包。player data 分段存放的文件会先拼接。

不带 type tree 的对象，按其所在文件声明的 Unity 版本取所属类的布局读取。`MonoBehaviour` 还需要脚本的布局：`--script-table` 指定一个 gzip 压缩、每行一个 JSON 对象的文件，含 `assembly`、`class` 和 `nodes`；`nodes` 按前序列出脚本字段的 `type`、`name`、`level`、`byteSize`、`typeFlags`、`version` 和 `metaFlag`，顶层字段的 level 为 1。对象按其类的引擎头加上这些字段读取。没有该表，或表中没有该脚本时，记录为错误 `no_layout`。每个对象都必须恰好读到其末尾；未能恰好读完的对象记录具名错误。

`ResourceManager` 对象的容器与 `AssetBundle` 对象的容器一样为资产命名，用的是游戏使用的加载路径。这些表的哈希计入本次运行所有资产的指纹。
