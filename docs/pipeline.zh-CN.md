# 管线

[English](pipeline.md)

管线是[派生图](architecture.zh-CN.md)的急切求值器。一次运行在单个进程中处理全部已配置区服的当前版本，所有区服共用一个目录与一个派生缓存。

## 阶段

| 阶段 | 工作 | 产出 |
|---|---|---|
| P0 计划 | 读取各区服当前的 asset version、应用版本与游戏数据修订号 | 若均与上一次完整运行相同，则无需工作 |
| P1 清单 | 下载并解析清单，按名称选取资源包 | 资源包列表，含声明的哈希、大小与依赖 |
| P2 取件 | 下载所选资源包，在数据流入的同时完成去混淆与哈希计算，并写入 store | 以内容哈希标识的资源包输入 |
| P3 索引 | 对每个资源包读取每个对象的字段，大数组按长度跳过；记录类、名称、容器路径、内容哈希与引用 | 对象记录与引用边 |
| P3b 解析 | 全部资源包完成索引后：将外部文件解析到资源包，将 `m_Script` 解析为类名，并写出对象文档 | 该版本完全解析的对象图 |
| **屏障** | 资产的闭包与名称取决于整个版本 | |
| P4 资产计划 | 每个转换器选取其根对象，并在引用边上计算闭包；确定名称（参见[身份](architecture.zh-CN.md#身份)）；计算指纹 | 待求值的派生；指纹已有输出的派生直接沿用，不读取任何字节 |
| P5 转换 | 在调度器下求值 convert 与 transform 派生 | 资产文档与文件字节 |
| P6 写出 | 将字节写入 store，已存在的内容跳过；在目录中记录派生 | store 对象与目录记录 |
| P7 视图 | 每个已启用的视图产生绑定；需要不同字节的视图产生 transform 派生 | 绑定 |
| P8 提交 | 核验每个已绑定的对象均以所记录的哈希存在于 store 中，随后推进版本指针 | 已提交的版本，附列其资产错误 |

## 不变式

- **增量以对象内容为单位，而非以资源包为单位。** 资源包重新打包而其中对象未变时，每个对象的哈希不变，因而每个资产的指纹不变。P2 与 P3 只对声明哈希发生变化的资源包运行；未变化的资源包沿用其已有索引。
- **指纹包含决定字节的全部因素**：转换器名称与版本、闭包中每个对象的内容哈希、转换器读取的每条数据表记录的哈希，以及编码器的名称、版本与参数。配置不改变输出路径、格式与编码参数，这些均由转换器与视图定义。
- **资产错误与运行失败相区分。** 资产错误是对资产求值的结果，即一个具名错误，与成功的输出同样确定。它不影响其他资产，不妨碍版本提交，并随版本一并列出。由于该资产没有成功的输出，下一次运行会再次求值。成员缺失（例如资源清单列出、但来源不提供的资源包）属于资产错误。运行失败指下载失败、写入失败或进程崩溃；只有运行失败会阻止提交。
- **工作的先后不影响输出。** 每项输出只取决于其输入，目录在每批结束时按键序写入。store 的内容以及按主键排序的目录内容均与线程数和调度顺序无关。
- **提交以版本为单位，要么全部生效，要么不生效。** P8 只在核验通过后推进指针。核验失败时，以固定名称报告失败的阶段，原有指针保持不变。

## 区服

全部区服在同一进程中运行。P0 至 P3 对各区服并行执行。在 P4 中，任一区服计算出的指纹可被其他区服直接找到，因此各区服之间共享的内容只转换一次。当两个区服对同一资源包声明的哈希相同时，下载阶段复用已为另一区服取得的资源包。

游戏数据表按区服分别存放。转换器的指纹只涵盖其实际读取的记录，因此即使两个区服的数据表在其他部分存在差异，只要某个资产所用的记录相同，该资产仍然共享。

## client 来源

客户端安装包内的资产经过同一条管线。P1 中的清单替换为安装包内的 player data 文件列表；P3 中，不带 type tree 的对象使用 `sekai-layouts` 中的字段布局表读取。每个对象都必须恰好读到其末尾；未能恰好读完的对象以原始字节写出，并附具名错误。
