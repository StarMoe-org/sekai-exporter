# 模型文件

[English](model.md)

模型文件是以 glTF 2.0 二进制文件保存的预制体层级：其节点、网格、蒙皮、混合形状与材质，采用 glTF 的坐标。携带三维模型的资产形式，例如[服装模型](costume.zh-CN.md#costume-model)，把它作为成员使用，并把其图像作为另外的成员加入。它本身不是资产形式。

## 1. 运行时

Moesekai 的 3D 服装查看器，通过 three.js 及其 glTF 加载器实现。它按节点名称找到模型的各个部件，按骨骼名称把一个部件的网格绑定到另一个部件的骨骼上，按通道名称驱动混合形状，按 Unity 的贴图属性读取每种材质的贴图，并把顶点颜色读作描边宽度。

## 2. 内容

该文件包含：

- 根及其下每个游戏对象各一个节点，按深度优先顺序排列，根在最前。节点具有游戏对象的名称、其 `Transform` 的局部位置、旋转与缩放，以及按 `Transform` 存储顺序排列的子节点。根是场景中唯一的节点；
- 每种组合对应一个 glTF 网格，组合由一个网格、其材质，以及（蒙皮使用它时）每个骨骼槽位的关节构成，并由绘制该组合的每个渲染器的节点引用。渲染器为 `MeshRenderer`（其网格取自同一游戏对象的 `MeshFilter`）与 `SkinnedMeshRenderer`。带有三角形的子网格即为一个图元。材质数多于子网格数的渲染器，会用每个多出的材质再次绘制其最后一个子网格，因此每个多出的材质各增加一个图元；
- 网格存储的每个顶点通道：`POSITION`、`NORMAL`、`TANGENT`、`COLOR_0`、`TEXCOORD_0` 及其后各项，以及对于蒙皮渲染器的 `JOINTS_0` 与 `WEIGHTS_0`；
- 每个蒙皮渲染器一个蒙皮，见下文。没有骨骼的 `SkinnedMeshRenderer` 不是蒙皮的；
- 每个混合形状通道一个变形目标，其中包含该通道帧的位置偏移，以及在网格具有法线与切线时它们的偏移，以稀疏访问器的形式保存。帧未存储的偏移（`hasNormals` 或 `hasTangents` 为 false）为零；
- 渲染器所用的每种材质一个材质，材质所用的每个 `Texture2D` 一个贴图、一个采样器与一个图像。

游戏对象未激活的节点，其 `extras.active` 设为 `false`。渲染器被禁用的节点，其 `extras.enabled` 设为 `false`。`m_RootBone` 为模型节点的蒙皮，把该节点放入 `extras.rootBone`。

网格为每个骨骼槽位保存一个绑定姿势，顶点的权重作用于各槽位。当网格为每个槽位保存骨骼名称哈希（`m_BoneNameHashes`）时，该哈希为骨骼在预制体根之下的路径的 CRC-32，写法与[组件文档](component-documents.zh-CN.md)书写节点路径的方式相同。每个槽位绑定到模型的一个节点：

1. 网格为每个槽位保存了哈希时，深度优先顺序中第一个路径的哈希与该槽位相同的节点；
2. 否则，或没有节点具有该哈希时，为该槽位在 `m_Bones` 中对应项所指定的节点，前提是该项已设置且为模型的节点。

一个节点只绑定到一个槽位：先按哈希绑定，按槽位顺序进行；然后按 `m_Bones` 绑定，同样按槽位顺序进行，已被绑定的节点会被跳过。骨骼先按哈希绑定，是因为哈希记录了网格所针对的骨骼：槽位的绑定姿势是该骨骼变换的逆，而渲染器的 `m_Bones` 可能列出其他骨骼。

蒙皮为每个已绑定的槽位保存一个关节，按槽位顺序排列，并以该槽位的绑定姿势作为其逆绑定矩阵。未绑定任何节点的槽位没有关节，任何顶点都不得对其加权。`JOINTS_0` 给出每个顶点所对应槽位的关节。

网格带有混合形状的 `SkinnedMeshRenderer` 所在节点具有 `weights`：对每个通道，取 `m_BlendShapeWeights` 中的对应项（列表较短时取 0），再除以该通道的满权重。

网格只存储骨骼索引而不存储权重时，顶点绑定到其第一个骨骼索引，权重为 1。权重为 0 的关节索引写为 0。

`mesh.extras` 为变形目标命名：

| 键 | 值 |
|---|---|
| `targetNames` | 每个目标的名称：即其混合形状通道的名称 |
| `fullWeights` | 对每个目标，在 Unity 尺度下，其帧完全生效时的通道权重 |

变形目标的 glTF 权重，即 Unity 通道权重除以其满权重。

`material.extras.unity` 按存储内容保存材质：

| 键 | 值 |
|---|---|
| `shader` | 着色器的名称（`m_ParsedForm.m_Name`），材质没有时为 `null` |
| `renderQueue` | `m_CustomRenderQueue` |
| `keywords` | `{ "valid": […], "invalid": […] }`，取自 `m_ValidKeywords` 与 `m_InvalidKeywords` |
| `textures` | `m_SavedProperties` 中的每个贴图属性，按名称列出：`{ "texture": <索引或 null>, "scale": [x, y], "offset": [x, y] }`。`texture` 为 glTF 贴图的索引；属性没有 `Texture2D`，或其图像为高动态范围图像时，为 `null` |
| `floats`、`ints`、`colors` | 每个保存的属性按名称列出。颜色为 `[r, g, b, a]`。材质未存储整数属性时，`ints` 为空 |

属性按存储顺序排列。同一名称存储多次的，保留第一个值。

JSON 无法表示的数，写为字符串 `"NaN"`、`"Infinity"` 或 `"-Infinity"`。

`pbrMetallicRoughness.baseColorTexture` 为 `_MainTex` 的贴图；`_MainTex` 没有时，为 `_BaseMap` 的贴图。它供不读取 `extras.unity` 的程序预览用：`metallicFactor` 为 0，`roughnessFactor` 为 1，其他材质字段都不由属性推导。

贴图的采样器依照其 `m_TextureSettings`。`m_WrapU` 与 `m_WrapV` 给出 `wrapS` 与 `wrapT`：0（repeat）为 `REPEAT`，1（clamp）为 `CLAMP_TO_EDGE`，2（mirror）为 `MIRRORED_REPEAT`。`m_FilterMode` 给出过滤方式；`m_MipCount` 大于 1 时带有 mipmap：

| `m_FilterMode` | `magFilter` | 无 mipmap 时的 `minFilter` | 有 mipmap 时的 `minFilter` |
|---|---|---|---|
| 0 (point) | `NEAREST` | `NEAREST` | `NEAREST_MIPMAP_NEAREST` |
| 1 (bilinear) | `LINEAR` | `LINEAR` | `LINEAR_MIPMAP_NEAREST` |
| 2 (trilinear) | `LINEAR` | `LINEAR` | `LINEAR_MIPMAP_LINEAR` |

每个图像位于文件之外。其 URI 为 `texture/<n>.webp`，其中 `n` 从 0 开始计数图像，并指向同一资产中角色为 `texture/<n>` 的成员；该成员为与[贴图形式](texture.md)的 `image` 成员形式相同的图像。

## 3. 来源

根是资产形式所选定的 `GameObject`。模型包含根的 `Transform` 子树、其游戏对象的组件，以及渲染器所引用的一切：网格、材质、着色器与贴图，它们可能位于其他资源包中。

| 情况 | 结果 |
|---|---|
| 某个游戏对象的组件，或渲染器所引用的对象，无法读取 | 该对象的错误 |
| 网格没有顶点、被压缩、使用可变的骨骼权重，或有一个不是三角形列表的子网格 | 错误 `unsupported` |
| 某个顶点通道的格式或分量数不在本页所列之中 | 错误 `unsupported` |
| 某组贴图坐标紧随在缺失的一组之后 | 错误 `unsupported` |
| 某个混合形状通道的帧数不恰为一个 | 错误 `unsupported` |
| 某个顶点的权重作用于未绑定模型任何节点的骨骼槽位 | 错误 `unsupported` |
| 蒙皮渲染器的网格没有骨骼索引，或带权重的骨骼索引无法装入 16 位 | 错误 `unsupported` |
| 某个贴图的环绕模式或过滤模式不在上表之中 | 错误 `unsupported` |
| 某个贴图无法解码 | [贴图形式](texture.md)的错误 |
| 某个变换、顶点位置、混合形状的位置偏移或绑定姿势不是有限数 | 错误 `malformed` |
| 网格没有为每个绑定姿势存储骨骼名称哈希，且骨骼数与绑定姿势数不同；某个顶点的权重作用于超出绑定姿势数的骨骼槽位；或渲染器的混合形状权重多于网格的通道数 | 错误 `malformed` |
| 某个混合形状帧使同一顶点移动两次，某个所存的偏移在其数据之外，或某个索引在顶点之外 | 错误 `malformed` |

支持的顶点通道为：位置、法线与贴图坐标，为 32 位浮点数；切线，为四个 32 位浮点数；颜色，为四个 32 位浮点数或四个归一化字节；骨骼权重，为至多四个 32 位浮点数；骨骼索引，为至多四个 32 位无符号整数。

## 4. 容器

GLB：带有一个二进制块的 glTF 2.0。贴图使用扩展 `EXT_texture_webp`，文件要求该扩展。带平铺或偏移的基础颜色贴图使用 `KHR_texture_transform`。

Unity 的左手坐标系通过对 X 取反，映射到 glTF 的右手坐标系：

| 值 | 映射 |
|---|---|
| 位置、法线，以及位置或法线的混合形状偏移 | `(-x, y, z)` |
| 旋转 | `(x, -y, -z, w)` |
| 切线 | `(-x, y, z, -w)` |
| 切线的混合形状偏移 | `(-x, y, z)` |
| 绑定姿势 `M` | `S M S`，其中 `S = diag(-1, 1, 1, 1)` |
| 三角形 | `(a, c, b)` |
| 贴图坐标 | `(u, 1 - v)` |
| 基础颜色的平铺 `(sx, sy)` 与偏移 `(ox, oy)` | 缩放 `(sx, sy)`，偏移 `(ox, 1 - sy - oy)` |

图像按从顶行开始存储，因此翻转的是贴图坐标而非图像。每个顶点属性、索引列表与逆绑定矩阵列表各有自己的缓冲区视图，起始于 4 字节的倍数处。所有索引都小于 65535 时，索引访问器为 16 位，否则为 32 位。关节为 16 位，权重为四个 32 位浮点数，字节颜色为归一化的。变形目标访问器没有缓冲区视图，以稀疏值保存不为零的偏移，索引为按递增顺序排列的 32 位索引；所有偏移都为零时，它没有稀疏值。顶点与变形目标的 `POSITION` 访问器带有 `min` 与 `max`。JSON 块中的数为所存的 32 位值，写为能读回同一值的最短十进制形式。

## 5. 正确性

上述映射是从 Unity 坐标到 glTF 坐标的基变换，按各类值的变换方式分别施用。文件由 Khronos glTF Validator 检查，须不报告任何错误；其关于带有变换或父节点的蒙皮节点的提示属于预期，因为层级保持预制体的存储方式。持续集成用合成对象构建预制体，并把节点、访问器、蒙皮、变形目标与材质与构建时所用的值相比较。在真实资源包上，每个文件的节点、访问器与材质，都与同一预制体的独立导出结果逐值比较，每处差异均予以说明。
