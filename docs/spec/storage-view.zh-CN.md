# storage 视图

`storage` 视图把一个版本的资产写成资源存储站提供的路径树。模块：`sekai-moesekai` 的 `storage_view`（feature `storage-view`）。`sekai-exporter update --storage <目录>` 发布该视图。视图版本：1。

## 1. 运行时

按路径读取资源存储站文件的网站与播放器。

## 2. 内容

| 资产形式 | 文件 |
|---|---|
| `texture`、`sprite` | 图像的 `<file>.webp` 与 `<file>.png` |
| `audio` | 每个 cue 一个 `<cue>.mp3`；有多个波形的 cue，其余为 `<cue>_2.mp3` 等 |
| `video` | `<base>.mp4` |
| `scenario` | `<file>.json` |
| `text` | 见下文 |
| `font` | `<file>.<扩展名>` |

其他成员（如 Sprite 文档）不属于该视图。`music/long` 下名称以 `_VR` 或 `_SCREEN` 结尾的 cue 不进入视图。

## 3. 来源

每个文件来自资产文档的一个成员。文件位于 `<bundle>/<名称>`，其中 `<bundle>` 是资产根对象所在的资源包，`<file>` 是资产名称的最后一段。`<base>` 是最后一段去掉 `.usm` 和形如 `-001` 的数字分段后缀。

以 `.bytes` 为扩展名存储的文本资产去掉该扩展名；位于 `music/music_score` 下的文件命名为 `<file>.txt`。其他扩展名的文本资产保留扩展名。

共享名称的资产遵循[架构](../architecture.zh-CN.md)中的命名规则。贴图资产名称中的 `@Texture2D` 不计入 `<file>`。多个资产落到同一路径时，贴图优先于精灵保留该路径，其次是资产名称排序最前者，其余不进入视图。

## 4. 容器

| 文件 | 参数 |
|---|---|
| WebP | 规范层的无损成员，不作改动 |
| PNG | WebP 成员的像素，8 位 RGBA，`png` 编码器 |
| MP3 | FLAC 成员的采样，320 kb/s 恒定码率，LAME，带记录编码延迟与补齐的标签帧 |
| MP4 | 规范层成员，不作改动；见[视频](video.zh-CN.md) |
| JSON 与文本 | 规范层成员，不作改动 |

变换也是派生：其指纹由视图版本、变换、编码器版本与成员哈希构成。第二次运行复用全部结果。

路径树的写入顺序见[发布](../publishing.zh-CN.md)。固定路径无法原子切换。

## 5. 正确性

将视图与由相同输入生成的参照树比较：文档逐值，图像比较解码后的像素，有损媒体比较格式契约（编码、容器、采样率、声道、时长差不超过一帧、码率档）。比较由 `tools/compare-storage` 完成。
