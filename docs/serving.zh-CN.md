# 服务

[English](serving.md)

发布按内容为每个文件命名：对象位于 `store/<aa>/<sha256>.<extension>`，其含义由索引承载。按路径访问文件的读取方，例如静态网站、查看器和下载工具，需要一个**解析器**把视图中的路径映射到对象。`sekai-exporter serve` 就是这样的解析器。它的核心，即 `sekai-serve` crate 的 `Resolver`，不做 I/O，因此同一份代码可以运行在其他宿主中，例如 S3 兼容存储桶前的边缘 worker。

解析器取代物化的路径树。路径树把每个文件复制或链接到固定路径，使存储的对象数随视图数成倍增加，并且无法原子地切换到新版本。解析出的路径树只存它的索引，所有视图共享同一批对象，新版本对所有路径同时生效。

## 视图及其路径索引

**视图**是建立在一次发布的对象之上的路径树：

| 视图 | 路径 |
|---|---|
| `canonical` | [发布](spec/publication.zh-CN.md)的路径：`<name>.asset.json`、`<name>.<extension>` 或 `<name>/<role>.<extension>` |
| `storage` | [storage 视图](spec/storage-view.zh-CN.md)的路径 |

视图的每次发布都向 store 写入一份**路径索引**，并在视图的指针 `<区服>/<视图>/current.json` 中以 `paths` 指向它。同一份指针还保存在 `<区服>/<视图>/versions/<发布版本>.json`，因此只要对象仍保留，较新的版本发布之后旧版本依然可访问。

路径索引由一个小的根文档和一系列**分块**组成，每个分块保存按字节序连续的一段路径，以及每个文件的哈希、扩展名、大小与媒体类型（[格式](spec/path-index.zh-CN.md)）。分块边界由路径的哈希而非位置决定，因此增加或改动少量路径的版本只改变包含它们的分块。未变的分块保留其哈希，发布下一个版本时只上传改变了的分块。

一次查找读取根，用二分查找找到范围包含该路径的分块，再在分块中二分查找该路径。根与分块只有在其字节的哈希与其名称一致时才被使用；解析器在[限制](#限制)之内把解码后的根与分块保留在内存中，因此在已读过的分块中查找不再读取任何内容。

## 路由

路由文件说明哪些 URL 路径指向哪些视图。路由按顺序尝试，第一条匹配的路由决定结果：

```json
{
  "routes": [
    { "pattern": "/jp-storage/{path}", "region": "jp", "view": "storage" },
    { "pattern": "/storage/{region}/{path}", "view": "storage" },
    { "pattern": "/{region}@{version}/{path}", "view": "canonical" },
    { "pattern": "/{region}/{path}", "view": "canonical" }
  ],
  "delivery": "bytes",
  "max_age": 60,
  "cors": "*"
}
```

模式以 `/` 开头，由 `/` 分隔的段组成。段可以是字面文本、占位符或两者兼有，例如 `{region}@{version}`；两个占位符之间必须有文本。占位符取所在段中直到其后文本首次出现之前的字符，这些字符必须构成名称：至多 200 字节的 ASCII 字母、数字、`.`、`_` 和 `-`，不全是点，也不是 Windows 保留给设备的名称，例如 `con` 或 `nul.json`。占位符取不到名称的路由不匹配，继续尝试下一条。第一条匹配的路由即使在其视图中没有该路径也决定结果，因此带字面文本的路由应排在更一般的路由之前。

| 占位符 | 含义 |
|---|---|
| `{region}` | 区服。由占位符或路由的 `region` 键给出，二者只能有一个 |
| `{view}` | 视图。由占位符或路由的 `view` 键给出，二者只能有一个 |
| `{version}` | 可选。已发布的版本：在该版本而非当前版本中解析路径 |
| `{path}` | 必需，且是最后一段。URL 路径的剩余部分经百分号解码后，就是视图中的路径 |

没有发布的区服、视图或版本视为不存在。

| 键 | 含义 |
|---|---|
| `delivery` | `"bytes"`：响应携带文件。`"redirect"`：响应重定向到 `store_url` 下 store 中的对象 |
| `store_url` | 使用 `"redirect"` 时 store 的 URL，对象位于 `<store_url>/<aa>/<sha256>.<extension>` |
| `max_age` | 当前版本的响应可缓存的秒数。默认 60 |
| `cors` | 存在时，作为 `Access-Control-Allow-Origin` 的值 |

路由文件若有其他键、有无效的模式，或某条路由重复给出或未给出区服或视图，解析器在启动时拒绝它。

## 响应

解析器回答 `GET`；对 `HEAD` 以 `GET` 的头回答，不带正文；对 `OPTIONS` 以 `204` 和允许的方法回答。没有路由匹配或视图中没有的路径返回 `404`，附带 `Cache-Control: public, max-age=<max_age>`。其他方法返回 `405`，超过 8192 字节的 URL 路径返回 `414`。无法读取的文件返回 `500`，附带 `Cache-Control: no-store`，原因列于[解析器检查什么](#解析器检查什么)。每个响应都带有 `X-Content-Type-Options: nosniff`，因此客户端只按给出的媒体类型看待文件。

使用 `"bytes"` 时，文件以 `200` 返回，附带：

| 头 | 值 |
|---|---|
| `Content-Type` | 文件的媒体类型 |
| `Content-Length` | 文件大小，或所请求范围的大小 |
| `ETag` | `"<sha256>"`，文件的哈希 |
| `Accept-Ranges` | `bytes` |
| `Content-Disposition` | `inline`，以路径的最后一段为文件名；不是 ASCII 时另以 UTF-8 的 `filename*` 给出，因此保存下来的文件保留其名称 |
| `Cache-Control` | 当前版本为 `public, max-age=<max_age>`，指定版本为 `public, max-age=31536000, immutable` |

单个字节范围 `bytes=<first>-<last>`、`bytes=<first>-` 或 `bytes=-<length>` 返回 `206`，附带 `Content-Range`。起点越过末尾的范围返回 `416`。请求多个范围，或 `If-Range` 不是文件的 `ETag` 时，返回整个文件。`If-None-Match` 列出文件的 `ETag` 或 `*` 时返回 `304`。

使用 `"redirect"` 时，文件以 `302` 重定向到其对象，附带相同的 `Cache-Control`。对象的 URL 永不改变，客户端或缓存可以任意长久地保留它。保存重定向文件的客户端以哈希为其命名；`"bytes"` 则保留路径中的名称。

设置 `cors` 时，每个响应都带有 `Access-Control-Allow-Origin`，并公开 `Accept-Ranges`、`Content-Disposition`、`Content-Range` 与 `ETag`；`OPTIONS` 允许请求头 `Range`、`If-None-Match` 与 `If-Range`。

视图的指针至多每 `max_age` 秒重新读取一次，因此新发布在这段时间内到达视图的每个路径，并且一次查找绝不会混用两个版本。不存在的指针也被记住同样长的时间，因此区服、视图或版本在首次发布后的 `max_age` 之内开始应答。

指定版本的指针也按同样的间隔重新读取，因为一个版本可以用同一个名称再次发布：`export` 每次运行都发布 `local`，`update --force` 把它找到的版本再发布一遍，转换器在此期间有改动时文件也随之不同。解析器在 `max_age` 之内以新文件应答。已经持有该指定版本响应的客户端或缓存，按其 `Cache-Control` 保留它，最长一年：解析器前面的缓存需要清除，浏览器则保留已有的内容。

## 解析器检查什么

解析器既不轻信请求，也不轻信发布。

请求只能通过路由指向文件。请求中的区服、视图和版本都是名称，因此它们指向的指针 `<区服>/<视图>/current.json` 或 `<区服>/<视图>/versions/<版本>.json` 是已发布根目录之下的文件。请求中的路径只在路径索引中查找，绝不成为文件名的一部分：被打开的文件是索引所指的对象 `<aa>/<sha256>.<extension>`。

发布只有在名副其实时才被使用。出现以下情况时，请求返回 `500`，宿主把原因写入日志：

- 指针无法读取、不是指针文档，或不是以 SHA-256 指向其路径索引；
- 路径索引的根或分块缺失或无法读取、其哈希与名称不一致，或不符合其格式；
- 指针超过 64 KiB，或根或分块超过 64 MiB；
- 索引给文件的扩展名不是名称，或给出的媒体类型不能作为头的值；
- 文件的对象缺失，或不是大小与索引一致的文件。服务在发送第一个字节之前就发现这一点，因此被截断的对象是一个错误，而不是中途断掉的响应。发送对象时不对其字节计算哈希。

失败的内容不会被记住：指针或对象恢复完好之后，下一个请求就会读取它。

## 限制

解析器记住的内容不随请求给出的名称增长。达到限制时，最久未使用的内容被丢弃，再次需要时重新读取。

| 记住的内容 | 限制 |
|---|---|
| 指针，无论是否存在 | 1024 个 |
| 解码后的路径索引根与分块 | 估算内存 256 MiB，由 `--cache` 设置 |

`sekai-exporter serve` 的服务还限制客户端占用的资源：

| 客户端占用的资源 | 限制 |
|---|---|
| 同时保持的连接 | 256 个，由 `--connections` 设置。更多的连接等到其中一个关闭 |
| 请求头部 | 16 KiB，须在 30 秒内发完；更长的头部返回 `431`。连接等待下一个请求的时间与此相同 |
| 没有任何字节收发的连接 | 60 秒后关闭 |

服务没有针对单个客户端的限制，也没有最低传输速率。在任何人都能访问的地方，它应位于反向代理或 CDN 之后。

## 运行解析器

```bash
sekai-exporter serve <output> --routes <file> [--listen <address>] [--threads <n>]
    [--connections <n>] [--cache <bytes>]
```

该命令由 `serve` feature 构建，`full` 包含它。`<output>` 是 `export` 或 `update` 的输出目录：指针从 `<output>/published` 读取，对象从 `<output>/store` 读取。服务只读取该目录，目录不存在时不启动。`--listen` 默认为 `127.0.0.1:8080`；`--threads` 是回答请求的线程数，默认为逻辑 CPU 数。`--connections` 与 `--cache` 设置上述[限制](#限制)；`--cache` 接受字节数，例如 `512M`。解析器提供 HTTP/1.1；TLS 与 HTTP/2 由其前面的反向代理或 CDN 负责。客户端可以在发完请求后关闭连接的发送方向，仍然得到应答。

## 其他宿主

核心是一个 `Resolver`：路由、检查、记住的内容与响应。宿主为每个请求开始一次查找（`Resolver::lookup`），给出自己时钟上的时间，并完成查找要求的读取，至多三次：视图的指针、其路径索引的根和一个分块，每次读取都带有允许给出的最大字节数。查找以一个响应结束：状态码、头，以及无正文、一段短文本，或某个对象的字节范围连同该对象应有的大小。宿主提供读取与时钟并写出响应，因此所有宿主的检查、记忆与应答都相同。`sekai-exporter serve` 的服务就是一个宿主，即该 crate 的 `server` feature 之下的 `sekai_serve::server`，其他程序同样可以运行它。存储桶前的边缘 worker 从存储桶读取，并按哈希缓存对象，因此指向同一对象的所有视图的所有路径共享一份缓存。
