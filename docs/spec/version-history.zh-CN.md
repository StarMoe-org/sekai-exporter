# 版本历史

[English](version-history.md)

版本历史按从新到旧列出视图的已发布版本，以及每个版本的文件数和它新增、删除、修改了多少文件。版本改动按路径列出这些文件。模块：`sekai-format` 中的 `version_history`。`sekai-publish` 在视图的每次发布时写出这两份文档，`sekai-serve` 经[发布文档的路由](../serving.zh-CN.md#版本历史)发送它们。格式版本：1。

## 1. 运行时

跨版本跟踪视图的网页与工具，例如区服文件的更新日志：一次请求得到全部版本及其计数，再一次请求得到所选版本改动的文件。之后可在该版本或上一版本中按路径读取文件，即[解析器](../serving.zh-CN.md)路由下的 `/{region}@{version}/{path}`。

## 2. 内容

**版本历史**包含键 `format`（`"version-history"`）、`version`、`view` 与 `entries`，视图的每个已发布版本一项，从新到旧：

| 键 | 值 |
|---|---|
| `published_version` | 发布版本的名称 |
| `revision` | 其最近一次发布的修订号 |
| `published_at` | 该次发布的时间，UTC，RFC 3339 格式，例如 `2025-01-02T03:04:05Z`。未知时省略 |
| `files` | 该版本的文件数 |
| `added`、`removed`、`changed` | 该版本相对上一版本新增、删除、修改的文件数。未知时三者一并省略 |

一个版本的**版本改动**包含键 `format`（`"version-changes"`）、`version`、`view`、`from`（上一个发布版本）、`to`（本版本），其后各项均按路径排序：

| 键 | 行 |
|---|---|
| `added` | `from` 在该路径没有文件时，每个文件一行 `{ "path", "size", "media_type" }` |
| `removed` | `to` 在该路径没有文件时，`from` 的每个文件一行 `{ "path", "size" }`，大小取其在 `from` 中的值 |
| `changed` | 字节与 `from` 中同一路径的文件不同时，每个文件一行 `{ "path", "size", "previous_size" }` |

两个版本中字节相同的路径不出现在任何一项中。一个版本条目的计数即这几个列表的长度，因此读取方在请求改动之前就知道它有多大。

## 3. 来源

一次发布的历史是视图上一次发布的历史加上本版本的条目：版本是新的时放在最前，版本以同一名称再次发布时替换最新的条目。没有上一次发布的发布以自己的条目开始一份历史，该条目没有计数。上一次发布没有历史时，新历史从该次发布的条目开始，该条目有其文件数，没有时间与计数。一个版本若没有改动视图上一次发布的任何文件、列表与失败，就不增加条目：视图保留上一次发布，连同其指针、历史与改动，名称仍是它发布时的版本。

新版本的改动是本次发布在上一次发布中改动的路径，见[发布文档](publication.zh-CN.md#5-正确性)。以同一名称再次发布的版本，其改动仍是相对上一版本的改动：取上一次发布所记录的改动，并把本次发布改动的每个路径与上一版本在该路径的文件重新比较。与上一次发布版本相同、修订号也相同的发布保留上一次的历史与改动。

以下情况下计数与改动未知，因而省略：视图已有发布时整体写出发布；版本再次发布而上一次发布没有记录改动；上一版本的指针或路径索引缺失。视图的第一次发布没有改动。

## 4. 容器

两份文档都是不含多余空白的 UTF-8 JSON，键按上述顺序，以 gzip 压缩。它们以 `<aa>/<sha256>.json.gz` 存储，媒体类型为 `application/gzip`，发布的指针以其 SHA-256 与大小在 `history` 与 `changes` 下指明它们（见[发布文档](publication.zh-CN.md)）。网页按解压[目录树](directory-tree.zh-CN.md#4-容器)的方式解压它们。

## 5. 正确性

读取方拒绝其他格式或版本的文档。

测试发布新增、删除、修改文件以及以相同字节重写文件的版本，并检查条目、计数与各行。测试再次发布一个版本，其中有的文件恢复为上一版本的字节、有的再次改动、有的是新文件，检查其改动仍是相对上一版本的改动，且没有该版本的指针时改动被省略。测试还检查以相同文件再次发布会保留这些文档，文件字节都相同的新版本（无论文件是否重写）会保留它之前的发布，重新发布的视图会延续其历史，没有历史的发布会从上一次发布开始一份历史。

## 6. 版本

格式版本：1。上述任何一项变化都会使版本变化。
