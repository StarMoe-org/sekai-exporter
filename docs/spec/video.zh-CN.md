# 视频

`video` 形式把 CRI USM 文件转换为浏览器与播放器可以播放的 MP4 视频。转换器：`sekai-convert` 中的 `video`（feature `video`）。形式版本：1。

## 1. 运行时

播放游戏影片的网页与媒体播放器。

## 2. 内容

一个成员：

| 角色 | 内容 |
|---|---|
| `video` | 视频流、USM 头中的帧率与画面尺寸，以及文件带有的音轨 |

## 3. 来源

根对象是容器路径以 `.usm.bytes` 结尾的 `TextAsset`。一个文件可以分成多段，存放在同一个包内，容器路径为 `<base>-001.usm.bytes`、`<base>-002.usm.bytes` 等。编号 001 的段是根；所有段的字节按编号顺序拼接，结果即 USM 文件。

ADX 音轨可能在其头部声明的采样数之前结束，此时解码它实际包含的完整帧。

| 情形 | 结果 |
|---|---|
| 1 到最大编号之间缺少某一段 | 错误 `missing_segment` |
| 文件不是恰好一条视频流，或该流不是 MPEG-1 | 错误 `unsupported` |
| 第一帧不以 MPEG-1 序列头开始（例如流被加密） | 错误 `unsupported` |
| 文件有多条音轨，音轨既不是 ADX 也不是 HCA，或 HCA 音轨被加密 | 错误 `unsupported` |
| 文件损坏 | 错误 `malformed` 或 `truncated` |
| 找不到 `ffmpeg` 程序 | 错误 `encoder_unavailable` |
| `ffmpeg` 程序执行失败 | 错误 `encode_failed` |

## 4. 容器

成员是索引位于文件开头的 MP4 文件，由 `mp4-h264-aac` 编码器（版本 2）通过 `ffmpeg` 程序写出，该程序须已安装并带有 `libx264`。可用环境变量 `SEKAI_FFMPEG` 指定程序。

| 流 | 参数 |
|---|---|
| 视频 | `libx264` 编码的 H.264：preset `medium`、4 Mb/s、GOP 12、最多 2 个 B 帧、`yuv420p`、2 线程，每个输入帧对应一个输出帧。宽或高为奇数的画面补齐为偶数 |
| 音频 | FFmpeg 编码器输出的 AAC，192 kb/s，采样率与声道数同音轨 |

容器不含元数据。相同的输入与相同的 FFmpeg 构建产生相同的字节；线程数固定，因为 `libx264` 的输出依赖于它。

## 5. 正确性

USM 文件的流分离已与独立的 USM 分离工具逐字节比对。MP4 文件的帧数与时长用 `ffprobe` 与 USM 头比对。
